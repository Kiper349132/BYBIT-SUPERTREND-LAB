BYBIT SUPERTREND LAB v0.8.0
=================================

ЧТО НОВОГО В v0.8.0 (этапы 0-1 аудита: надёжность, память, воспроизводимость)
------------------------------------------------------------------------------
Модель бэктеста и формулы оценок НЕ изменены: автоматический тест сравнивает их
бит-в-бит с v0.7.1 (tests/test_core_equivalence.py).

1. Продолжение прогона математически равно непрерывному прогону.
   После кнопки «Остановить», закрытия окна крестиком, Ctrl+C, аварии процесса
   (BrokenProcessPool), защитной остановки по памяти, жёсткого убийства процесса
   или отключения питания продолженный прогон даёт тот же TOP-100, те же
   устойчивые области, те же наборы fine/cluster-кандидатов, те же компоненты
   Adaptive V2 и тот же итог. Проверяется тестами tests/test_resume_equivalence.py
   и tests/test_gui_close.py (настоящее окно Tk).

2. Chunk-файлы — главный источник результатов.
   research\<прогон>\chunks\chunk_*.jsonl.gz содержат и результаты, и список
   завершённых в них блоков. index.json — только кэш: если он повреждён или
   удалён, он восстанавливается из chunk-файлов. Программа больше НИКОГДА не
   удаляет вычисления: непроверяемые файлы переносятся в quarantine\.
   Все служебные файлы пишутся через временный файл + flush + fsync +
   атомарную замену, предыдущая версия сохраняется как .bak.

3. Закрытие окна и Ctrl+C = кнопка «Остановить».
   Крестик Windows запускает ту же безопасную остановку: процессы расчёта
   останавливаются, готовые блоки записываются на диск, затем окно закрывается
   само. Повторное нажатие крестика предлагает немедленный выход (записанное на
   диск при этом не пострадает).

4. Память.
   - Расчётные процессы загружают только lab_core.py (numpy + numba).
     Tkinter, matplotlib, pandas и requests в них больше не загружаются
     (раньше: ~230 МБ на процесс только на импорты, теперь ~140 МБ).
   - Numba-код компилируется один раз и кэшируется на диске (cache=True);
     раньше каждый процесс каждого пула компилировал всё заново.
   - Свечи записываются один раз в research\<прогон>\market\*.npy, процессы
     отображают их в память (memory-map) — одна физическая копия на всех.
   - Индикаторы режима Adaptive V2 (EMA/ADX/ATR) считаются один раз.
   - Один пул процессов на весь прогон; max_tasks_per_child=400 — только страховка.
   - Результаты сразу пишутся в сжатый chunk на диске, а не копятся в RAM.
   - Защита учитывает и физическую RAM, и лимит выделения памяти Windows
     (RAM + файл подкачки).
   - Если процесс расчёта аварийно завершается, пул пересоздаётся автоматически
     (с меньшим числом процессов) и расчёт продолжается.
   - Осиротевшие процессы расчёта после аварии главного окна завершаются сами.

5. VALIDATION больше не влияет на поиск.
   Компоненты LONG/SHORT для Adaptive V2 выбираются по статистике только
   SELECTION-окон (поля sel_*). В v0.7.1 использовалась статистика всех окон,
   включая VALIDATION. Тест tests/test_leakage_and_workers.py меняет цены после
   начала VALIDATION и проверяет, что все решения поиска остались прежними.

6. Иерархический поиск (детерминированный, объяснимый).
   широкий грубый поиск -> поиск УСТОЙЧИВЫХ ОБЛАСТЕЙ -> локальное углубление ->
   очень мелкая сетка только локально -> Adaptive V2.
   Устойчивость точки = нижний квартиль оценок SELECTION всех соседей
   (плато, а не одиночный пик). Почему выбрана каждая область, записано в
   research\<прогон>\regions\*.json и попадает в отчёт.

7. Прочее: история, взятая из сохранённого CSV, обрезается ровно до
   запрошенного периода; START.bat / SELF_TEST.bat / DIAGNOSE.bat исправлены
   (раньше START.bat без лаунчера py всегда писал «Python was not found»);
   журнал ротируется (20 МБ x 3); ZIP-отчёт содержит только файлы текущего
   прогона, использованные свечи и хвост журнала.

ВАЖНО: незавершённые прогоны v0.7.x продолжить нельзя — логика выбора областей
и исправление VALIDATION изменили поиск. Старые папки research\ не удаляются.

ЗАПУСК
1. Запустить START.bat (нужен Python 3.11+).
2. Выбрать режим и таймфреймы, нажать «Запустить исследование».
3. После завершения прислать reports\CHATGPT_REPORT_*.zip.

Если исследование было прервано, при следующем запуске с теми же настройками
программа предложит продолжить его. Продолжение использует свечи, сохранённые
в папке прогона, поэтому результат совпадёт с непрерывным расчётом.

ПРОВЕРКИ
- SELF_TEST.bat — быстрая проверка (1-2 минуты).
- python -m pytest tests — полный набор регрессионных тестов.
- python tools\loadtest.py --minutes 20 — нагрузочный тест памяти на вашей
  машине (нужен pip install psutil): график RAM главного процесса и каждого
  расчётного процесса во времени.

СТРУКТУРА
BYBIT_SUPERTREND_LAB.py  крошечный запускатель
lab_gui.py               интерфейс
lab_core.py              расчётное ядро (единственное, что грузят процессы расчёта)
lab_search.py            иерархический поиск, пул процессов, продолжение
lab_storage.py           надёжное хранилище research\
lab_data.py              загрузка свечей Bybit
lab_report.py            CSV и ZIP-отчёт
lab_cli.py               запуск без интерфейса

ЧТО ЛЕЖИТ В research\<прогон>\
run.json           настройки и отпечатки данных
market\            свечи этого прогона (для точного продолжения)
chunks\            ВСЕ результаты (главный источник)
index.json(.bak)   кэш списка chunk-файлов
stage_cache\       ускоритель продолжения (можно удалить — восстановится)
regions\           какие устойчивые области выбраны и почему
quarantine\        файлы, не прошедшие проверку (не удаляются автоматически)
COMPLETE.json      прогон завершён

ВАЖНЫЕ ОГРАНИЧЕНИЯ МОДЕЛИ (не менялись в v0.8, это этап 2)
- Funding пока не учитывается.
- Просадка считается по закрытым сделкам, не по плавающей внутри сделки.
- Каждое 21-дневное окно начинается без позиции.
- Полная модель ликвидации и маржинальных уровней не реализована.
- Большое число тестов повышает риск случайных победителей.
- Ни один исторический тест не гарантирует будущую прибыль.
